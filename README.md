# haddadkuwait.com — restructured offline snapshot

This repository contains a browser "Save As…" capture of <https://haddadkuwait.com>
(حداد مظلات الكويت — Arabic, RTL), restructured into a maintainable static site.

The original capture was 633 files / ~51 MB of loose HTML and duplicated `*_files/`
folders. It is now a small source tree (`src/`) that builds the servable site (`site/`)
with one shared header and footer.

## Repository layout

```
src/
├── partials/
│   ├── header.html        # shared header: top contact bar, logo, desktop nav
│   │                      # + الخدمات dropdown, mobile menu
│   └── footer.html        # shared footer + floating call/WhatsApp buttons
└── pages/
    ├── index.html         # /            (the "skeleton" home page)
    ├── about.html         # /about/
    ├── contact.html       # /contact/
    ├── faq.html           # /faq/
    ├── projects.html      # /projects/
    ├── site-map.html      # /site-map/
    ├── services.html      # /services/
    └── services/
        ├── pvc.html
        ├── أبواب-حديد-خارجية-في-الكويت.html
        ├── أفضل-تصميم-وتنفيذ-للمجالس-الخارجية-في.html
        ├── تركيب-مظلات-الكويت.html
        └── سياج-الحدائق-الأخضر-في-الكويت.html

site/                      # BUILD OUTPUT — generated by build.py, do not edit
├── <route>/index.html     # one assembled page per src/pages file
└── assets/
    ├── css/               # 11 stylesheets, named by role (tailwind-*, fonts-*,
    │                      #   swiper-*, phone-input-*, consultation-*, journey-*)
    ├── js/                # 29 scripts, named by role (react-*, swiper-*, store-*,
    │                      #   rtk-query-*, ui-*, …; hash kept as a short suffix)
    ├── fonts/             # 18 woff2: urbanist-*, inter-*, roboto-*
    ├── icons/             # favicon.ico, kw.svg
    └── images/            # 26 files

build.py                   # assembles src/ → site/
```

Each `src/pages/*.html` file holds only what is unique to that route: its `<head>`
(title/meta/preloads), its `<main>` content, and its hydration payload. At the
`<!--@include header-->` / `<!--@include footer-->` markers the shared partials are
injected. `{{CLS:<href>}}` tokens in the header become the active/inactive nav-link
styling for that page (e.g. `active="/about/"` highlights من نحن).

## Editing and running

```bash
# edit files under src/, then rebuild:
python3 build.py

# serve (root-relative /assets/ paths require the root to be site/):
python3 -m http.server 8000 --directory site
# open http://localhost:8000/
```

Any static server works (`npx serve site`, `caddy file-server -root site`, nginx, …).

## What the snapshot actually is

The capture is the **rendered HTML output of a Next.js (App Router) application**, not
its source. Each page ends with a React Server Components hydration payload
(`self.__next_f.push([...])`) that must stay byte-consistent with the rendered markup —
so the shared markup is extracted as **build-time partials**, not runtime includes,
and the payload blocks at the bottom of each page are intentionally left minified.

## What changed in this refactor

1. **Skeleton extracted.** The header (which the snapshot had saved in two variants —
   some pages were missing the الخدمات dropdown entirely) was normalised to the full
   desktop variant and moved to `src/partials/header.html`; the byte-identical footer +
   floating buttons moved to `src/partials/footer.html`. Every page now shares them.
2. **Readable markup.** Previously each page was ~3 very long minified lines. HTML is
   now indented, JSON-LD blocks are pretty-printed, and each file carries a comment
   header explaining its role.
3. **Meaningful file names.** `f116dc912b2ffba2.js` → `react-dom-f116.js`,
   `f245d8ae8d445bd6.css` → `tailwind-f245.css`, `5c8bbc…-s.p.woff2` → `urbanist-2.woff2`,
   etc. All references were rewritten, including the chunk map inside the Turbopack
   runtime. A 4-char hash suffix is kept on JS/CSS for traceability to the build output.
4. **Dead markup removed.** Duplicate `<script>` tags that the Save-As capture emitted
   twice for the same chunk were deduplicated during the build.
5. **Beautified assets.** All CSS and JS chunks were run through formatters for
   readability (formatting only — no behaviour change).

## Inventory

**Pages (12):** home, services listing, 5 service detail pages, projects, about,
contact, FAQ, site map. (The blog listing and its 4 articles were removed earlier per
request.)

**Shared partials:** header (contact bar + nav + mobile menu), footer + floating
call/WhatsApp buttons.

**Assets:** 26 images, 18 woff2 fonts, 2 icons, 11 CSS files, 29 JS files.

**JavaScript roles:** `bootstrap`/`turbopack-manifest`/`rsc-runtime`/`flight-client`
(Next.js runtime), `react-dom`/`react-core`/`vendor-polyfills`, `store`/`rtk-query`/
`api-client` (Redux Toolkit Query → `server.haddadkuwait.com/api`), `swiper`/`sliders`/
`ui-carousel` (carousels), `motion` (framer-motion), `visibility`, `ui-widgets`/`ui-cart`
(lucide icon chunks), `router`, `layout-*`/`page-shell` (page components), `shared-*`,
`utils`, `app-runtime`, `next-vendor`.

## Blog removal

`/blog` and the four article pages were deleted with every rendered reference (nav
entries, the homepage popular-posts section, the site-map entry, four `blogs-*.webp`
images). A few `/blog` strings remain inside the `__next_f` hydration payloads as dead
data — editing the positional payload arrays would corrupt them.

## External dependencies

| Dependency | Decision |
| --- | --- |
| Webfonts | **Localised** into `assets/fonts/` |
| `favicon.ico` | **Localised** into `assets/icons/` |
| `server.haddadkuwait.com` (CMS/API + `/uploads/*` media) | **Remains external** — see limitations |
| `res.cloudinary.com`, `images.unsplash.com` | **Remains external** — `og:image`/JSON-LD metadata and a few inline backgrounds |
| `wa.me`, Instagram, Facebook, YouTube, Pinterest, X, LinkedIn | **Remain external** — outbound links |
| `haddadkuwait.com` canonical/OG URLs | **Remain external** — SEO metadata |

No analytics, tag manager or third-party script tags were present in the snapshot.

## Known limitations (offline)

- **No backend in the snapshot.** The app fetches content via RTK Query from
  `https://server.haddadkuwait.com/api`; offline these requests fail, so anything that
  re-fetches after hydration (search, cart/wishlist, live listings, carousel data) stays
  inert. Pages still display their pre-rendered content.
- **Contact form submissions go nowhere** for the same reason.
- **Hero slider background images** point at `server.haddadkuwait.com/uploads/banners/…`
  and load only when online.
- **Five service URLs** referenced by the site were never saved and remain absolute
  links to production: `/services/commercial-shades`, `/services/luxury-pergolas`,
  `/services/outdoor-enclosures`, `/services/retractable-roofing`,
  `/services/terrace-systems`.
- **Payload data is duplicated.** The hydration payload at the bottom of each page still
  embeds its own copy of the nav/footer markup — that is required for hydration to work
  if the backend is reachable, and is dead data otherwise.
